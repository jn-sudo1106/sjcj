# 演示二：数据抽取、转换与清洗 · 需求与提示词（2026-11-17）

## 1. 具体需求

**研报 PDF 结构化入库**：把宏观研究报告 PDF 变成可查询、可回查的指标库。

- 样本：`设计稿/设计方案/国内报告 1019.pdf`（《财经智库》2026 年第 4 期，张明《中国国际收支结构的重大变化》，24 页）。本次实测取前 8 页（去图片，正文约 4700 字）。
- 公开发表的论文，对外演示前确认可以引用。

三步：

| 步骤 | 平台能力 | 输入 → 输出 |
| --- | --- | --- |
| 抽取 | PDF 抓取节点“解析内容”（`/api/answer/document-extract`） | PDF → 文献信息 + 数据点（按原文，不换算） |
| 转换 | 规则处理节点，AI 生成脚本 | 数值统一为“亿美元”，时间统一为年份 |
| 清洗 | 同上 | 去重、限定词数值标为非精确、无法识别的保留原值 |

抽取只忠实于原文，换算和清洗交给确定性的脚本，便于核对和复现，这本身就是一条治理原则。

## 2. 抽取提示词（第 2 版，已在 186 实测）

模型：DeepSeek `deepseek-v4-flash`；outputFormat `json`；需求描述：

> 从宏观研究报告 PDF 中抽取文献信息，以及正文里关于中国国际收支的定量数据点，用于建立可回查的指标库。

系统提示词：

```
你是研究报告数据抽取助手。只依据上传 PDF 的原文抽取，不推断、不补全、不换算单位。
输出要求：只输出一个 JSON 对象，不要输出解释文字，不要用 Markdown 代码块包裹。
JSON 结构：{"文献": {...}, "数据点": [...]}。
一、“文献”字段：TITLE 标题、AUTHOR 作者、AFFILIATION 作者单位、JOURNAL 刊名、ISSUE 卷期、PUB_DATE 出版时间、PAGES 起止页码、KEYWORDS 关键词、DOI、ABSTRACT 内容提要。按原文填写，原文没有的填 null。
二、“数据点”：抽取正文中的金额类数据（如亿美元、万亿美元）和比例类数据（%、个百分点），每条一个对象，字段为：INDICATOR 指标名称、PERIOD 时间、VALUE_RAW 数值、UNIT_RAW 单位、QUALIFIER 限定词、DIRECTION 方向、SOURCE_TEXT 原文句子、PAGE 印刷页码。
数据点规则：
1. 不抽取“连续 N 年”“其中有 N 年”这类年数统计。
2. 并列或递进的多个数值依次对应多个年份时，拆成每个年份一条。例如“2023—2025 年……分别达到 a、b 和 c”“比重由 a 提高至 b，再到 c”都拆成 2023、2024、2025 三条。
3. 累计值、均值、区间统计（如“2020—2025 年累计达到”“2001—2020 年长期均值”）保留原文区间，不拆。
4. 数值和单位保持原文写法，例如“4.07 万亿美元”写 VALUE_RAW="4.07"、UNIT_RAW="万亿美元"，不要换算；负号保留；百分比写 UNIT_RAW="%"，“个百分点”照写。
5. 数值前后带“超过、低于、约、近、以上、以下”等限定词的，照常抽取，并把限定词写入 QUALIFIER；没有限定词填 null。
6. DIRECTION 只取原文明确写出的“顺差、逆差、增长、下降、回撤”之一，没写就填 null。
7. SOURCE_TEXT 截取包含该数值的原句，不超过 80 字，便于回查。
8. 不抽取图表标题、资料来源、页眉页脚、参考文献和脚注编号；只有定性描述、没有具体数值的句子不抽取。
```

## 4. 转换清洗提示词（第 2 版，已在 186 实测）

规则处理节点（测试配置 1910014），模型 DeepSeek `deepseek-v4-flash`。

- 输入字段：`指标名称:INDICATOR,时间:PERIOD,数值:VALUE_RAW,单位:UNIT_RAW,限定词:QUALIFIER,方向:DIRECTION,原文句子:SOURCE_TEXT,页码:PAGE`
- 输出字段：`指标:INDICATOR_STD,年份:YEAR,时间区间:PERIOD_STD,数值:VALUE_STD,单位:UNIT_STD,是否精确值:IS_EXACT,异常原值:ERR_RAW,异常说明:ERR_REASON`

需求描述：

```
把研报抽取出的数据点转换为统一口径。入参字段名为 INDICATOR、PERIOD、VALUE_RAW、UNIT_RAW、QUALIFIER、DIRECTION、SOURCE_TEXT、PAGE，值都是字符串，可能为空或 "null"，按缺失处理。
返回的 JSON 对象字段名必须严格为 INDICATOR_STD、YEAR、PERIOD_STD、VALUE_STD、UNIT_STD、IS_EXACT、ERR_RAW、ERR_REASON，不要改名、不要增减。
1. INDICATOR_STD：指标名称去掉空白和全角空格。
2. 时间：单一年份（如“2025年”“2025年底”）取 4 位年份写入 YEAR，PERIOD_STD 也写该年份；区间（如“2020—2025年”）YEAR 留空，PERIOD_STD 写“2020-2025”；没有年份时两者都留空。
3. 金额统一换算为“亿美元”：万亿美元乘 10000，亿美元不变，百万美元除以 100；结果保留 2 位小数。“%”和“个百分点”不换算，单位分别写“%”“百分点”。其他单位（包括人民币单位“亿元”“万亿元”）一律不换算，按无法识别处理。
4. IS_EXACT：QUALIFIER 不为空（超过、低于、约等）时写 0，数值照常换算；否则写 1。
5. 数值为空、数值无法识别或单位无法识别时：VALUE_STD 和 UNIT_STD 留空，ERR_RAW 写原文“数值+单位”（如“3.2万亿元”），ERR_REASON 写“数值缺失”“数值无法识别”或“单位无法识别”；不得猜测或填默认值。识别正常时 ERR_RAW、ERR_REASON 为空字符串。
```

系统提示词沿用前端默认值 `DEFAULT_RULE_SYSTEM_PROMPT`（要求 `main` 为第一个定义的函数）。

去重放在入库环节，按“指标 + 年份 + 数值 + 单位”判重，不放进单行脚本。

### 6.2 走查中发现的问题（演示前需处理或绕开）

1. **PDF 节点的表绑定没写进配置**：界面选了输入 2101867、输出 6910002，保存后配置 1910015 的 `inEntryType`/`entryTypeId` 都是空。原因：`app/src/utils/flow/nodeConfigPayload.ts:368` 只读 `collectCfg.outputTable`/`cfg.outputTable`，PDF 节点的绑定存在 `execCfg`。影响：后端按配置找不到输出表，Excel 导入报「configId 与实体 ID 不匹配」，正式运行时抽取结果也无处落表。本次已按界面本该保存的值手工补写配置 1910015。
2. **「测试脚本」用错了数据**：点测试后跳到规则节点的数据视图，默认显示**输出表**（空），需要手动切到「输入 6910002」才有行。若从别的节点视图带脚本路径测试，`buildCodeParams` 取不到 `ruleCfg.inputFields`，传空参数（`main() missing 8 required positional arguments`）。
3. **测试参数名与生成时的字段名不一致**：新建表的字段编码按旧平台约定存成「编码-列号」（如 `INDICATOR-K1`，`TableEditDialog.vue:242`）。生成脚本时 AI 看到 `INDICATOR-K1` 会写成参数 `INDICATOR`；界面测试却原样传 `INDICATOR-K1`（`ResultView.vue:1873` `buildCodeParams` 用 `field.prop`），执行端点报 `unexpected keyword argument 'INDICATOR-K1'`。老表（如 6300344 的 `tdate`）不带后缀，所以之前没暴露。修复方向：测试与正式执行时按 `splitProp` 去掉 `-Kn` 后缀再传参，并在生成提示里给出同样的参数名。
4. **「解析内容」结果不入库**：只能复制或另行导入，演示时需要说明，或由后端补「解析结果写入输出表」。
5. **新建表「导入字段」弹窗自带 3 行示例字段**（code/name/url），清不掉，会和输入内容拼在一起，需手工删除；物理表名输入框也会把自动生成值和输入拼接。
6. **配置 1910015 的 `prompt` 为空**：界面提示「系统提示词已保存」，但配置的 prompt 字段没有内容，系统提示词可能存在节点提示词选择里，未进一步核实。
7. **提示词边界**：「2025年较2024年」被转换脚本当成区间写成 `2025-2024`。下一版描述补一条：比较表述（A 年较 B 年）YEAR 取 A，PERIOD_STD 写 A，不当区间。

### 6.5 节点类型提示词模板（2026-11-17 晚）

核实结论：系统设置「节点类型 → 提示词模板」与画布节点读的是同一张表 `sense_db.cfg_llm_node_prompt`（186 MySQL 9907）。

- 186 前端构建未设 `VITE_FLOW_PROXY_TARGET`（`constants/deployGates.ts`），节点走旧接口 `/api/prompt/list`（9040 data-engine）；该服务实体无 `template_use`，不区分「生成配置 / 生成 Python 代码」，只按分类 + 节点类型名称 + 启用筛选。设了该变量的构建走 runner-management，读 `templateUse=config`。
- 规则处理节点：表绑定齐全后进「编排配置」即取模板，取到就覆盖系统提示词（本页手改过的除外）。
- PDF 抓取节点：进 Tab 无条件取模板；系统提示词同时给「生成配置」（XML）和「解析内容」用，**不要给 PDF 抓取配模板**，否则会覆盖演示节点上的抽取提示词。

已在「规则处理（910）→ 生成配置」新增模板 ID 69：分类 `rule`、启用、默认，系统提示词与前端内置 `DEFAULT_RULE_SYSTEM_PROMPT` 相同。新旧两条读取路径都返回 69；演示规则节点打开编排配置时请求 `/api/prompt/list?category=rule&node_type_name=规则处理` 并拿到 69。
