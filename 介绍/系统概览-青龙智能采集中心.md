## 1. 一句话定位

面向政企的**网页/多源数据采集与治理平台**：把「采集源 → 流程编排 → 规则处理 → 入库 → 指标 → 监控」串成一条链，并在两处用大模型提效：

- **生产侧**：用自然语言生成采集代码、规则脚本、抓取配置，以及摘要、打标签、翻译、PDF 抽取、语音转写等内容加工节点；
- **消费侧**：「智能问数」，用自然语言查数、出图、做业务诊断（目前前端为演示版）。

登录页口号：「高效采集 · 智能解析 · 数据驱动未来」。

## 4. 核心业务链路

```
源（网站/公众号/文件…）
  └─ 绑定流程（可从模板新建，多源共用一个流程）
       └─ 节点编排：采集类 → 规则类 → 引用类 → 通知类
            └─ 下发到处理机执行（MQ 队列）→ 入库（输出表/字段映射）
                 └─ 数据中心 / 文件中心 / 指标中心
                      └─ 监控中心告警 → 任务中心重发
```

**节点类型**（流程画布里可用）：

- 采集类：网页抓取、浏览器抓取、文件下载、公众号抓取、网页登录
- 规则类：数据处理、规则处理（解析/清洗/校验/去重/结构化/提取/字段映射）、数据监控、数据校验
- 内容加工：文章生成摘要、翻译、文章打标签、PDF 抽取、视频提取音频 + 语音识别
- 引用/通知：指标引用、提取数据发邮件、异常告警、自定义节点

## 5. AI 能力详解（介绍重点）

### 5.1 大模型接口管理（智能能力 · 底座）

- 统一登记多个大模型接口：名称、类型（**代码生成 / 对话生成**）、模型标识（示例 `hy3`）、接口地址、超时、是否流式、默认接口。
- 内置**接口测试台**：可编辑系统/用户提示词，实时看流式输出，复制最终 HTTP 请求。
- 接口可绑定到具体的「代码生成服务器」（按地址自动匹配或手工关联），并配置 Agent 工作空间（输入/代码/输出目录、浏览器调试端口 `cdp_port`）。这说明代码生成走的是能操作浏览器的 **Agent 式生成**，而不只是一次性补全。

### 5.2 AI 生成采集代码（最有特色）

> ✅ 已在环境 `47.120.11.60:2806/sjcj`（后端 118.25.96.217）实际验证，下面的数据来自该环境。

入口：节点上的「站点脚本生成」→ 生成任务 → 任务中心。

**实际部署形态**

| 代码生成服务器 | 地址 | 挂载的大模型接口 |
| --- | --- | --- |
| home171 | 192.168.1.171，工作空间 `D:\codeserver\workspace` | **WB-AGENT（默认，Agent 代码生成，模型 hy3）**、WB-Chat（对话生成，hy3）、WB-AGENT-9222 |
| DESKTOP-J6SE2RE | 192.168.1.25，工作空间 `D:\coder\workspace` | Gemini Agent、Gemini Chat（gemini-3.5-flash-lite） |

两台都是内网 Windows 机器，向平台登记后保持在线，平台把任务派给它们执行。所以**同一套流程可以切换不同的模型或 Agent**（hy3 / Gemini）。

**真实使用情况**：任务中心共有 21 条代码生成任务，都是上市公司官网的新闻列表采集，例如天博智能 603448、马矿股份 601123、华大海天 920288、金钛股份、格林生物、贝特利。生成的文件按域名命名，例如 `www.qftemb.com.py`。同一个网站会多次「修改后重新生成」，也有一条失败记录。

**一次完整生成（任务 98b1f60c，天博智能）**：

1. 平台组装提示词：目标 URL、文件名、保存目录，以及输出字段定义（title / url / publish_date / publish_date_std / src_name）。系统提示词分六章写清工程约束：参考文件检查、与公共入口 `newslink.py` 的调用契约（`scrape(url) -> list[dict]`，键必须是字段 ID 字符串）、采集范围、职责边界、文件与依赖、输出格式。
2. 调用 `POST http://192.168.1.171:6000/wb/agent`，传入模型 hy3、工作空间目录、浏览器调试端口 `cdp_port`，超时 600 秒。
3. **Agent 自主执行**（过程输出可以完整回看）：读取参考代码 `demo.py` → **实际抓取目标网页并分析 DOM**（发现列表区有 3 个 `<ul>`、13 个 `<li>`，其中只有 6 条是真正的新闻）→ 写出更稳健的解析器 → **对着线上页面跑通验证** → 写入指定路径 → 再导入文件执行 `scrape()` 做一次端到端自测。
4. 平台收集结果文件，**自动提交并推送 Git**（版本 c49128b，仓库路径 `links/1401218/sites/www.qftemb.com.py`），然后关联到流程节点的部署配置。

介绍要点：这不是“让模型写一段代码”，而是 **Agent 看真实网页、写代码、自测、入库的闭环**，平台负责约束、调度、留痕和上线。

- 给定目标列表页 URL 和样例代码，由模型生成完整的 Python 采集脚本（约定 `scrape(url)` 返回 title/date/url/summary/content）。
- 提示词有明确的工程约束：不照搬样例站点的选择器；不写 MQ、数据库、调度逻辑；导入模块时不发起网络请求。
- **异步任务化**：任务写入数据库，由在线的代码生成服务器领取，过程输出实时回传；可取消、可查看完整模型请求。
- **可迭代**：「修改后重新生成」，填写修正要求（如「发布日期取错了，请使用列表中的日期」），同时保留历次版本。
- **工程闭环**：生成结果自动提交到指定 Git 仓库目录（按网站或队列命名），并关联到流程节点的部署配置，随处理机下发运行。

### 5.3 AI 生成规则脚本 / 抓取配置（规则工作台）

规则处理、数据监控、数据校验、抓取节点都支持「用自然语言描述 → 生成脚本或配置」：

- 例如：「打开列表页提取表格前 20 行数据」→ 生成抓取配置 XML；「我想对 XX 进行如下监控……」→ 生成监控脚本。
- 可选模型供应商与模型，展示**思考过程**，生成后可在线测试脚本，再保存并绑定到节点。
- 生成时会检查字段一致性，提醒「字段未在已选字段中，抓取到的数据无法入库」。

### 5.4 AI 内容加工节点

| 节点 | 能力 |
| --- | --- |
| 文章生成摘要 | 大模型生成摘要，提示词来自提示词表 `cfg_llm_node_prompt` |
| 文章打标签 | 大模型自动打标签 |

### 5.5 提示词模板中心

- 按节点类型维护公共提示词模板：系统提示词、用户提示词模板、变量定义、输出结构（JSON）、示例输入/输出。
- 支持默认模板、启停；删除前自动备份；**节点里已保存的提示词不会被模板修改回写覆盖**（模板与实例解耦）。

### 5.6 智能问数（NL2SQL / 数据智能体）

前端设计的交互形态：

- 自然语言提问 → **交互澄清**（智能体给出候选分析口径卡片，用户选定维度与时间窗）→ 展示思考过程与生成的 SQL → 执行结果（指标卡、趋势图、明细表）→ 诊断与处置建议 → 智能追问（如「导出 TOP3 为 CSV」「为成功率低于 85% 的网站自动生成告警规则」）。
- 支持多会话历史、深度思维（Reasoning）开关、自动生成图表，标注「基于 Agent SSE 流式接口驱动」。
- ⚠️ **当前状态**：已部署的两个环境（124.223.180.186:9999、47.120.11.60:2806/sjcj）的前端都**没有 `/ai-chat` 路由和菜单入口**；配置数据（数据字典、推荐问题等，银行经营指标场景）在 124 环境中是真实的。压缩包里的前端是**演示版**。`AiChat` 页面没有任何接口调用，示例对话（异常任务排查、32,450 行扫描等）全部写死在前端。介绍时需说明这是交互原型，或先确认后端问数服务的进度。

问数的**配置侧是真实实现的**，体现了 RAG / NL2SQL 的工程化：

- 向量表管理：源表 → 向量表，配置召回数、匹配度、字典表类型、预处理与清洗规则、列映射，支持一键同步。
- 选表规则、表改写、实体改写（简单替换/正则替换）。
- 问句词典：**大模型调用前替换 / 调用后替换**（简单、正则、字段替换）。
- 七类模板：表模板、自动补全、问句改写、数据索引、数据字典、提示词、分词。

## 8. 智能问数入口建议

**推荐方案：侧栏「首页」分组下单独放一个「智能应用」分组，第一项是「智能问数」；同时在顶栏加一个全局入口。**

```
首页
  采集资产总览
智能应用            ← 新增分组，放在第二位
  智能问数
源工作区 / 全局数据 / 流程与规则 / 运行与监控 …
问数配置            ← 保持原位，只对管理员可见
  基础配置 / 模板配置 / 问数系统配置
```

理由：

1. **问数是“用数”，配置是“管数”**。现在侧栏只有「问数配置」，这是给管理员调词典、模板、向量表用的；业务用户的问数入口不应该藏在配置里，而要和配置分开，并放在显眼的位置。
2. **位置靠前，便于演示和高频使用**。总览看全局，问数做下钻，两者都在首屏，介绍时可以从总览的异常直接切到问数追问。
3. **单独成组，方便以后扩展**。之后可以把 AI 代码生成任务、提示词模板等 AI 能力也收进这个分组，形成「智能应用」这个对外卖点。
4. **实现成本低**。菜单本来就由「菜单配置」动态下发，加一个菜单项、按角色授权即可；但当前部署的前端**缺少 `/ai-chat` 路由**，需要用包含 AiChat 页面的版本重新构建，并接上真实的问数接口。

**补充入口（二期）**：

- 顶栏右侧加一个「问数」按钮或快捷键，打开右侧抽屉，在任何页面都能提问。
- 在监控中心、数据中心等页面里带上下文提问，例如在某个异常源上点「问一问」，自动带上源 ID 和时间范围。前端演示版里已经设计了“针对异常源自动创建监控告警”这类追问，和这个思路一致。

不建议放在：「问数配置」里（混淆用户与管理员角色）、「辅助工具」里（定位是排障小工具）、仅作为悬浮球（不利于演示和展示）。
