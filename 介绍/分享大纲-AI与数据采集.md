## 一、分享定位与目录

面向客户的数据治理分享。主线是一句话：**采得到不等于用得上，数据要经过治理才能交付。**

AI 让“采到数据”变得容易，治理问题因此更突出：脚本多了、来源多了，口径更容易乱，问题更难发现。围绕四个治理环节组织内容：

1. **接入规范**：新来源按统一的流程模板接入，字段与入库表一致，不各写各的。
2. **口径统一**：日期、标题、链接等字段统一格式；识别不了的保留原值并标出，不拿猜测值填补。
3. **质量监控**：任务成功不代表数据可用，要定时检查数据是否按时、完整入库，异常要通知并留下回执。
4. **可追溯**：每条数据都能回到来源链接、生成脚本和处理记录，查询结果可以复核。

AI 在其中的位置：采集脚本、转换脚本、检查脚本都可以由 AI 生成；平台负责把它们纳入治理，也就是统一执行、统一口径、持续检查和全程留痕。

贯穿案例：持续跟踪上市公司官网新闻。投研只是案例背景，不另起一条功能介绍线。

**开场讲法**：

“假设我们每天要跟踪一批公司官网的新闻。把数据采下来，现在 AI 已经能帮上很大忙；真正难的是采下来之后：格式统一不统一，今天的数据到没到齐，出了问题能不能查到原因。今天就讲这部分，也就是数据治理。”

正文不安排前端开发经历、页面巡礼、代码规模，也不展开提示词与 Agent 细节。

## 三、逐页内容与讲法

每页按“上屏内容 / 讲法 / 过渡”组织。各页要核实的事项统一列在第四节，不在讲解时提及。

### 第 1 页：封面与问题：采得到，不等于用得上

**上屏内容**：标题“智能体时代的数据采集与治理实践”、副标题“以青龙智能采集中心为例”、分享人和日期占上方一条；主体是一张真实网页截图和三类问题，各配一个例子：

- **口径不一**：同一个“发布日期”，有的写 `2026年11月10日`，有的写 `2026/11/9`，有的只写“近日”。
- **悄悄停更**：任务每天显示成功，但详情表已很久没有新增。
- **无法追溯**：一条数据有问题，说不清来自哪个页面、哪个版本的脚本。

**讲法**：先用开场讲法引出案例，再讲三类问题：“这三个问题有个共同点：任务本身不报错。所以光看任务成功率发现不了，需要专门的治理手段。”不单独做封面页和目录页。

**过渡**：“那平台在采集链路上是怎么治理的？”

### 第 2 页：一条链路，四个治理环节

**上屏内容**：链路图，四个治理环节标在对应位置。

```
外部来源 → 采集入库 → 规则转换 → 查询使用
  [接入规范]       [口径统一]      [可追溯]
  └──────── [质量监控]：定时检查执行与产出，异常通知 ────────┘
```

- 质量监控画成横跨整条链路的底线，不画成主链路上的一个步骤。
- AI 生成的三类脚本（采集、转换、检查）用同一种颜色标出，对应“AI 写，平台治理”。

**讲法**：“AI 擅长写出一次能跑的脚本。但业务要的不是一次能跑，而是每天有数据、口径一致、出了问题能查。平台做的就是这四件事：新来源按模板接入，字段按统一口径转换，产出持续检查，过程全部留痕。下面一个一个看。”

**过渡**：“先看接入：一个新网站，怎么按规范接进来。”

### 演示一：AI 脚本智能采集（接入规范，5 分钟）

**治理要点**：交付标准是入库数据与原网页一致，不是“脚本生成成功”。

**演示步骤**（操作约 4 分钟）：

1. 打开目标新闻列表页，指出要采集的字段。
2. 在源中查看目标流程与节点，以及给 AI 的生成要求。
3. 在任务中心打开已完成的生成任务，说明 AI 读取真实页面、生成脚本并自测。不现场等待生成。
4. 打开对应的采集结果，与原网页核对标题、日期和链接。

**讲法**：“这里有两个步骤：生成脚本和执行采集。生成成功不算完成，要看到数据入库、字段和原网页一致才算交付。”

操作画布时顺带一句：这套流程是模板，同类网站套用后只需配置网址等基本信息。不展开，不打开第二个实例。

**过渡**：“数据采进来了，但很多内容还在 PDF 里，格式也不统一，怎么变成能用的数据？”

### 演示二：数据抽取、转换与清洗（口径统一，5 分钟，重点）

**治理要点**：把非结构化内容变成字段，把字段变成统一口径；识别不了的保留原值并标出，不拿猜测值填补。

**案例**：采集到的一份公告或新闻附件是 PDF。三步处理，都用规则处理节点完成：

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 抽取 | PDF 文件 | 正文文本（PDF 转 Markdown） |
| 转换 | 不同写法的发布日期，如 `2026年11月10日`、`2026/11/9` | 统一为 `2026-11-10`、`2026-11-09` |
| 清洗 | 标题首尾空白；识别不了的日期如“近日” | 去掉空白；日期留空，原值记入异常字段 |

**演示步骤**（操作约 4 分钟，在 186 上）：

1. 打开一条采集到的 PDF 原文，指出内容在 PDF 里，无法直接查询和统计。
2. 打开“PDF 转 MD”规则处理节点和它的输出，对照 PDF 原文看抽取出的正文。
3. 打开转换清洗节点：展示一句话描述和 AI 按描述生成的脚本（会前生成好，不现场等待）。
4. 点“测试脚本”，用样例行试跑，对照处理前后结果，停在“近日”那一行。

转换清洗用的描述：

> 标题去首尾空白；发布日期统一为 YYYY-MM-DD，识别不了就留空并记下原值，不要用当天日期填补。

| 处理前（标题 / 日期） | 处理后（标题 / 日期 / 异常原值） |
| --- | --- |
| `  公司发布新产品  ` / `2026年11月10日` | `公司发布新产品` / `2026-11-10` / — |
| `签订重大合同` / `2026/11/9` | `签订重大合同` / `2026-11-09` / — |
| `董事会决议公告 ` / `近日` | `董事会决议公告` / 空 / `近日` |

**讲法**：“采下来的原始内容不能直接用。第一步是抽取，把 PDF 里的内容变成文本和字段；第二步是转换，把各种写法统一成一个口径；第三步是清洗，去掉脏数据。规则用一句话描述，由 AI 生成处理逻辑，测试通过再保存。注意最后一行：日期识别不了时留空并保留原值，不拿当天日期填上。错的数据比空的数据危害更大，因为没人知道它是错的。”

上面的对照表和一张 PDF 抽取前后对照图做成备用截图，现场受阻时直接用它讲。能演示到哪一步以会前在 186 实际走通的为准，没走通的步骤用截图讲，不说成已在流程中自动执行并入库。

**过渡**：“数据抽出来、洗干净了，任务每天也显示成功，是不是就可以放心用了？”

### 演示三：AI 脚本监控（质量监控，5 分钟）

**治理要点**：检查的对象是数据，不是任务状态；检查本身和通知也要留下记录。

**上屏内容**：

- 问题引子（脱敏）：源列表显示“新入、成功”，但详情表已很久没有新增。列表只反映主表，详情表停更在列表上看不出来。
- 检查链路：AI 生成检查脚本 → 试跑 → 保存 → 定时执行 → 运行记录 → 异常通知与回执。
- 三个检查点：
  1. 任务是否按时触发并执行。
  2. 数据是否在约定时间内入库，数量与关键字段是否符合要求。
  3. 检查本身是否执行，异常通知是否成功送达。

**演示步骤**（操作约 4 分钟，在 186 上）：

1. 用 30 秒讲问题引子。
2. 打开一条 AI 生成的检查：说明被检表、时间字段、检查窗口，展示脚本与试跑结果。
3. 打开运行记录：定时执行和立即运行都会留下结构化结果（检查条数、异常条数、耗时）。
4. 打开一次真实异常（检查 1104）：异常事件和邮件回执（状态“已发送”），说明检查结果与通知结果分开记录。

**讲法**：“检查脚本也由 AI 来写，平台负责每天跑，并留下检查和通知的记录。没有收到告警不等于没有问题，也可能是检查没跑，或者通知没发出去，所以两者要分开看。新闻这类数量不固定的源，检查条件要参考发布规律和历史产出，不能机械地定死条数。”

**过渡**：“回到 PPT，讲最后一个治理环节。”

### 第 3 页：可追溯：数据能回到来源（2.5 分钟）

**治理要点**：每条数据都能回到来源链接、生成它的脚本版本和处理记录。

**上屏内容**（截图，不现场操作）：一条追溯链，用演示一的同一条数据：入库数据 → 来源链接 → 对应的生成任务与脚本版本 → 采集任务记录。

**讲法**：“刚才三个演示里，平台都留下了记录：提示词、生成过程、脚本版本、执行记录、检查记录。数据有疑问时可以一路查回去。后面做查询和问数也依赖这一点：答案能回到原始记录，用的人才敢用。”

问数不展示；被问到时说明当前状态。

**过渡**：“最后用三句话收个尾。”

### 第 4 页：三点收获（2 分钟）

**上屏内容**：

- **采得到不等于用得上**：AI 让采集变容易，治理决定数据能不能用。
- **交付看数据，不看任务状态**：入库数据要核对，产出要定时检查，检查和通知也要留痕。
- **宁可空着，不要错数**：口径统一时保留异常原值，每条数据都能查回来源。

**讲法**：用同一个网站案例回顾四个环节（接入规范 → 口径统一 → 质量监控 → 可追溯），然后进入问答。
