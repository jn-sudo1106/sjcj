## 三、各环节要点

### 1. 开场：数据采集的痛点与 AI 的机会（5′）

- 业务需要的信息分散在成千上万的网站、公众号、PDF、视频里，**格式各不相同、经常改版**（举例时可以带一句：比如做投研要跟踪几千家上市公司官网）。
- 传统做法：一个网站一个脚本，人工开发并维护，**数量一多，维护成本就会失控**。
- 抛出问题：能不能让 AI 来写采集代码，人只负责把关？

### 2. 产品设计逻辑与理念（10′）

**设计逻辑：一条数据流水线**

```
源（网站 / 公众号 / 文件）→ 流程（可模板化，多源共用）→ 节点（采集 / 规则 / 加工 / 通知）
  → 处理机执行 → 数据中心 → 指标中心 → 监控告警 / 智能问数
```

**设计理念（建议提炼成 4 句话）**：

1. **一切皆节点**：采集、清洗、AI 加工、告警都是可编排的节点，AI 不是外挂，而是流水线上的一道工序。
2. **流程模板化**：上千个网站共用少数几套流程模板，差异只在“网站脚本”这一层，而这一层交给 AI 生成。
3. **人在环路**：AI 生成，人来审核和修正（“修改后重新生成”），结果进 Git，可回滚、可追溯。
4. **模型可插拔**：模型接口统一管理（hy3 / Gemini 都能切换），不绑定某一家模型。

可展示的截图：流程中心、节点类型列表（23 种）、侧栏分组。

### 3. AI × 数据：两个飞轮（6′）

| | 生产侧：AI 造数据 | 消费侧：AI 用数据 |
| --- | --- | --- |
| 做什么 | 生成采集代码、规则脚本；摘要、打标签、翻译、PDF 抽取、语音转写 | 自然语言问数、生成 SQL、出图、业务诊断 |
| 价值 | 采集覆盖面更广、上线更快 | 降低用数门槛 |
| 关键设计 | 约束式提示词 + Agent 自测 + Git 入库 | 问句改写、实体改写、向量召回、数据字典 |

一句话：**数据越全，AI 越准；AI 越强，数据越多。**

### 4. 演示一：AI 生成采集代码（15′，全场核心）

**演示路径（47 环境）**：

1. 源管理 → 打开一个上市公司新闻源（如天博智能 603448）→ 进入流程画布。
2. 打开“生成步骤脚本”，展示系统提示词与用户提示词（重点讲字段 ID 约束、职责边界）。
3. 选择模型接口（WB-AGENT / hy3），提交生成任务。
4. **任务中心 → 查看详情**，按顺序讲解：
   - 模型调用：实际的 HTTP 请求（工作空间、cdp_port、600 秒超时）
   - **过程输出**：Agent 读参考代码 → 抓真实网页 → 发现 13 个 `<li>` 中只有 6 条是新闻 → 写解析器 → 线上自测 → 写入文件
   - 生成结果：已提交并推送 Git（c49128b）
5. 展示“修改后重新生成”：填写修正意见，例如“发布日期取错了，请使用列表中的日期”。
6. 对比同一网站 hy3 和 Gemini 两次生成的结果（天博智能就有两条记录），说明模型可以切换。

⚠️ 一次生成要几分钟：**开场时先提交一个新任务**，讲到这里时刚好跑完；同时准备好已完成的任务 98b1f60c 作为兜底。

### 7. 产品经理的 AI Vibe Coding：这个前端是怎么搭出来的（12′）

**开场一句话**：刚才演示用的每一个页面，都是我作为产品经理用 AI 写出来的。

**规模**（来自前端构建包，可以直接放上 PPT）：

| 指标 | 数值 |
| --- | --- |
| 技术栈 | Vue 3 + Vite + Element Plus + TypeScript（`vue-tsc` 类型检查） |
| 页面 | 约 20 个一级模块、10 个菜单分组；26 个页内页签、107 个弹窗 / 抽屉 |
| 代码量 | 源码 1406 个文件；自己写的代码压缩后约 3.4 MB，和引用的第三方库差不多大 |
| 承载数据 | 47 环境：122 个网站、19,253 个采集源，其中上市公司 6,564 个 |

#### 页面巡礼：用真实页面讲 Vibe Coding（按演示顺序，每页 1–2 分钟）

每一页都按同一个结构讲：**这个页面解决什么问题 → 我怎么让 AI 做出来 → 一个能看出“产品思维”的细节。**

**① 采集资产总览 `/overview`：先有全局视角**
- 页面内容：资产总数、今日采集任务、成功率、告警；按“基金类 / 股票类 / 舆情类”展示采集网站全景，下面是资产类型分布、近 7 日趋势、重点采集源、实时运行动态。
- 讲点：这是采集资产的“驾驶舱”（顺带一句：基金、股票、舆情这些投研分类就是在这里定义的）。产品经理先定义要看哪些指标、怎么分类，AI 负责把图表和布局做出来。
- ⚠️ 讲之前先确认：页面上部分数据（重点采集源的同步时间停在 6 月、导出按钮）看起来是演示数据。

**② 源管理 `/collect`：把 2 万个源管得住**
- 页面内容：系统目录 / 我的分组 / 我的视图 / 我的收藏 / 最近打开；按网站聚合成卡片（“上市公司(已复核) 6564 / 6564 个源”“研究观点：挪威主权基金、新加坡政府投资公司、摩根士丹利…”）；多条件筛选，标签可以直接用业务语言（“日期错误待重跑”“正文缺失”）。
- 讲点：数据量大了以后，**组织方式**就是产品设计。这一页体现了产品经理对“怎么找到要处理的那个源”的思考。

**③ 编排画布 `/canvas`：工作台式的操作**
- 页面内容：左侧是源列表（如上市公司 6,564 个源），中间是流程画布，右侧是节点配置；顶部可以同时打开多个页签（最多 8 个）。
- 讲点：这是交互最复杂的页面。值得讲的细节：
  - 节点没保存就切换时，提示“不是丢失改动，是整个节点没了”，而不是一句笼统的“有未保存内容”。
  - 页签满了会自动关闭最右侧的一个，并告诉用户可以重新打开。
- 这些提示语都是产品经理对 AI 提的要求，体现的是对用户会在哪里犯错的预判。

**④ 流程中心 `/flows`：模板化**
- 页面内容：流程模板（如“境内-列表（接口）+详情（接口）+附件下载”，链路是证券之星港股公司报道 → 详情 → 规则处理）、从模板新建、归集到模板、复制流程。
- 讲点：复制流程时让用户选择“新增一套配置（推荐）”还是“复用原配置（改一边两边都变）”。把技术上的引用关系翻译成用户能做的选择，这是产品经理的价值。

**⑤ 系统设置 → 代码生成服务器 / 大模型接口：AI 也是被管理的资源**
- 页面内容：两台生成服务器在线；每台挂着自己的模型接口（WB-AGENT / hy3、Gemini Agent），有测试台、能复制请求。
- 讲点：这一页是全前端里**最大的单个页面**（压缩后约 100 KB），说明在 AI 能力的“可配置、可测试、可追溯”上投入最多。

**⑥ 任务中心 → 代码生成详情：留痕**
- 页面内容：提示词 / 过程输出 / 模型调用 / 生成结果 / 任务参数五个页签。
- 讲点：和演示一呼应。用 AI 写系统的人，最清楚 AI 需要被看见、被追溯，所以把这一点做进了产品里。

#### 从页面里能讲出的经验和踩坑

都是在真实页面里能指出来的东西，比空讲更有说服力：

| 现象（可以现场指给大家看） | 背后的 Vibe Coding 经验 |
| --- | --- |
| 智能问数先做出完整的交互原型（前端演示版），再接真实接口 | **原型先行**：先用 AI 把体验做出来，让大家看到效果、对齐需求，再接后端 |
| 规则资产里有“演示”“二期接入”的占位按钮 | 同上；但要管理好“演示”和“真实”的边界，避免被误以为已上线 |
| 监控中心里，一条数据监控规则把自然语言条件“数据延迟超过阈值 delay_minutes gt 30 连续3次”直接拼进了 SQL，每次运行都报语法错误 | **生成结果必须校验**：自然语言到 SQL / 脚本之间要有检查和测试环节（需确认这条规则是不是 AI 生成的） |
| 文件服务地址在构建时写死为 `127.0.0.1:9102` | **本地能跑 ≠ 上线能用**：环境相关配置要单独管理，这是 AI 写代码最常见的遗漏 |
| 124 和 47 两个环境的前端版本不同（124 多一个“SQL模板配置”页签） | 迭代快以后，**版本和环境管理**要跟上（BUILD_INFO 记录提交号和构建方式就是一个好习惯） |
| 大量细致的提示语、未保存提醒、自动保存、批量提交可暂停 / 继续 | **AI 负责实现，产品经理负责想到**：这些需求不会自己冒出来 |

### 8. 干货：两层 AI 写代码的共同方法论（8′）

把第 4 节（产品让 AI 写采集代码）和第 7 节（我用 AI 写产品）放在一起对照，得出同一套方法：

| 方法 | 产品里：AI 写采集代码 | 我自己：AI 写前端 |
| --- | --- | --- |
| **写清契约，而不是只写需求** | 规定 `scrape(url) -> list[dict]`，Key 必须是字段 ID 字符串 | 待补充：你怎么向 AI 描述页面、接口、数据结构 |
| **划清职责边界** | AI 只写网站脚本，不碰 MQ、数据库、回执；公共入口 `newslink.py` 由人维护 | 待补充：哪些部分你不让 AI 动 |
| **允许拒绝，禁止编造** | 参考文件缺失或字段映射不清时直接停止；不准用当前日期冒充发布日期 | 待补充：AI 编造接口或字段的例子 |
| **让 AI 自己验证** | Agent 对线上页面实测，发现 13 个 `<li>` 里只有 6 条是新闻 | 类型检查 `vue-tsc`、构建、自己点一遍 |
| **结果工程化** | 输出进 Git、绑定节点、全程留痕 | Git 管理、构建信息记录（BUILD_INFO） |
| **人在环路迭代** | “修改后重新生成”，失败记录也保留 | 小步迭代、每次改完都验证 |

可以补充一组数据：代码生成任务数、成功率、平均耗时（需要从任务中心统计）；你自己的开发周期、迭代次数。
