## 二、目标链路（会议定稿 + 后端核对）

```
新建 / 编辑监控
 ├─ 读「节点提示词模板」数据监控类型（nodeType 610）：系统提示词 + 用户提示词，变量按表单选项填充
 ├─ 生成脚本：选智能体（可全选资源池）→ 代码生成任务 → 提交 Git  monitor/<sourceId>/<监控ID>.py
 ├─ 保存：check_conf 只存 scriptPath + archiveId（后端建议，契约 4），不再存正文 / 文件服务路径
 └─ 执行计划：交给统一调度（契约 5），监控不再自建调度
```

后端已定：监控标识用 `ck_source.id`（契约 3）；Git 信息复用生成归档 `/site-scripts/generation-state`（含 repoId / directoryId / gitCommit / pushed）。

#### 第 2 批前端已先做（2026-11-18，按给后端的接口需求实现，**后端未支持前生成会被拒**）

- 监控编辑器「检查方式」新增**生成方式**：`智能体 · 提交 Git` / `内置接口`（现有 data-process，供应商 + 模型）。**新建监控默认智能体**（用户 2026-11-18 要求）；没有 `generation` 键的旧记录打开仍是内置接口，不擅自改它的生成方式。
- 智能体模式字段：智能体（启用的 agent / gemini-agent，首项「全选 · 任意空闲智能体」）、代码仓库（通用或 610 类型、启用）、仓库目录（启用的 610 目录，没有则退通用目录，默认取「生成默认目录」）；加载失败在字段下方显示原因。选项在智能体模式下加载（新建打开即加载），内置模式不请求 Runner。

- 结果：候选脚本正文 + 归档文件路径；脚本区显示 Git 提交状态（commit / 已推送 / 仅本地提交 / 失败）。

- 未做：参考文件（默认带框架主程序）——等后端确认框架主程序路径后再加；已保存记录的提交详情要后端按 archiveId 单条查询。

## 六、规则处理节点「智能体配置」（2026-11-18 已实现）

- 规则处理节点（600）的「智能体配置」页签与网页抓取一致：顶部「生成配置 | 智能体」，**默认智能体**。
  「智能体」= 复用 `SiteScriptGeneratorDialog`（智能体 / 仓库目录 / 提交位置 / 参考文件 / 生成归档 / 提交 Git）；原「设置业务规则 + 供应商 / 模型 + 生成脚本」保留在「生成配置」里。
- 规则节点本身有 sourceId / flowId / stepId / configId，走现有生成任务即可，**不依赖契约 7**；核对后端源码：带 configId 的归档路径不做 `scrape(url)` 校验，规则脚本（`def main()`）可以通过。
- 没有 600 的节点提示词模板时，弹窗兜底不再用网页抓取口径：系统提示词 = 节点保存的规则系统提示词或 `DEFAULT_RULE_SYSTEM_PROMPT`（main 入口、入参出参），用户提示词 = 规则描述 + 输入表 + 入参字段（弹窗新增 `fallbackSystemPrompt / fallbackUserPrompt`）。
- 数据监控 / 数据校验 / PDF / 文章摘要 / 打标签 / OCR / 音视频 / 翻译等「按规则式渲染」的节点不出现这组切换，各走原链路。
- 2026-11-18 调整：
  - Tab 名改为「内置接口 / 智能体 · 提交 Git」（网页抓取节点仍叫「生成配置 / 智能体」）；内置接口里注明「旧方式：脚本存文件服务、不提交 Git」。
  - 「设置业务规则」（含「脚本编辑」）挪到两个 Tab 上方共用，智能体的默认用户提示词随它更新。
