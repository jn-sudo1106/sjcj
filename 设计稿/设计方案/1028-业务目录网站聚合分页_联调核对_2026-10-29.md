# 业务目录下的网站展示：前后端聚合分页接入

日期：2026-10-29（Asia/Shanghai）。前后端本地实现、测试和构建完成，尚未部署到真实业务环境。

## 最终行为

全部网站视图每次查询、翻页、改变页大小或网站排序，调用一次 `POST /api/v1/site/sourceScopePaged`。请求使用 JSON body。前端直接展示服务端当前页、完整总数、命中源数、未关联数及最多 5 条预览，不再全量下载网站目录或扫描全部命中源，不再逐卡补查统计。

网站排序独立于源列表排序：最近编辑为默认，另支持网站 ID、当前条件命中源数各自升降序。收藏置顶由服务端在分页前完成。收藏写入成功后重新查询网站页，不在浏览器把当前页随意重排。

当前页全站数据量为已确认 0 时展示“数据 0 条”；未知时展示“数据 —”。不再因为有源且统计为 0 就拉取整站源，也不拿命中预览的数据量充当全站总量。`count=0` 仍按需求方确认的旧口径筛 DATA_CNT IS NULL。

网站筛选候选只在用户展开时最多请求 50 个，输入名称远程搜索；不会成为网站卡片首屏的前置条件。

## 目录及源列表兼容

`SourceDirPanel` 保留系统/业务二选一、默认不选、点名称仅直属、勾选含子孙及半选语义，输出压缩后的 `directory={kind,mode,selections}`：

- 勾父目录：只传父 ID 与 includeDescendants=true，不先展开整树。
- 全选：mode=all，不提交所有节点 ID；空树仍是空范围。
- 取消选中父目录中的某个分支：沿已知祖先路径拆分仍选中的兄弟子树，不把半选祖先传成全子孙。保持原有半选时不纳入祖先直属源的勾选口径。
- 懒加载只随用户展开树节点发生；搜索结果需要祖先时只补祖先链，不枚举整个子树。
- 清空：mode=none。目录请求失败有真实错误提示，不提交一份不完整范围冒充成功。

网站与源列表共用同一筛选组件实例。切换后保留名称、状态、数据量及目录；网站页码、页大小和排序保留。源列表排序不混入网站请求。

后端 sourcePaged 增量支持可选 JSON directory，复用同一目录树解析与权限校验。SourceCond、SourceExample 和原 SourceMapper 增加仅在提供 directory 时使用的分支；不传时保持旧行为。网站预览“+N”继续使用 sourcePaged，带同一网站、源条件和原始目录范围，每次最多取 50 条，支持继续加载。浮层搜索明确搜索已加载的源。

导出/发送等按当前查询逐页收集的操作自然保留 directory。按筛选范围调整来源组是 query 绑定接口，目录字段专门编码为 `directory.kind`、`directory.mode`、`directory.selections[0].id` 等 Spring 嵌套参数，避免被丢弃或变成 `[object Object]`；后端将 selected/all 识别为有效范围，再通过同一个解析器过滤。测试仅验证参数和绑定，未执行真实归属修改。

sourcePaged.directory 会批量附加当前源页的网站名称，不为“所属网站”列下载全网站目录。旧调用不增加该查询，siteName 为 null 时也不改变旧 JSON 字段。

源列表的“业务目录”辅助列仍沿用既有成员缓存加载；它只在源列表视图启动，不阻塞网站视图。旧移动目录、按目录批量定时等操作只在用户明确触发时才转换旧接口需要的目录 ID，不作为网站查询的前置步骤。

收藏/最近打开的旧卡片路径保持原有实现；本次针对“全部网站 + 系统/业务目录”的聚合路径。

- 后端全量：161 项通过，包含网站聚合 SQL、可选 sourcePaged 目录分支、嵌套 query 参数绑定，以及旧调用不增加目录查询的验证。
- 前端 Vue/TypeScript 类型检查和 Vite 构建通过；后端 Maven package 通过。
- 改动涉及文件 ESLint 无错误、无警告。
- 全量检查发现原 HEAD 已存在的 `group-res/groups` mock 清单漏项，本次补齐契约登记，保持原有 mock 行为，没有新增 live 放行。

本地浏览器用固定测试数据验证了：父目录压缩选择、取消子目录半选、全选 all、命中数排序、第二页、切换源列表再切回后保留第二页和排序，以及“+N”携带同目录按 50 条分页。验收同时覆盖默认窄视口与 1280×800 笔记本视口。截图中明确标注“固定数据，非 MariaDB 性能实测”。

SQL 语义测试使用 H2 fixture；生产 SQL 仍使用 JDBC 绑定参数。H2 对嵌套 CTE 的参数和定义缓存有兼容差异，测试适配器只处理 fixture 的字面量和内部 CTE 名，不参与生产。
