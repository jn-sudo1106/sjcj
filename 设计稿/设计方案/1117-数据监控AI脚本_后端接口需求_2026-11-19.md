## 一、一句话

前端已经按下面的约定改完并上线 217（`56275ee8`）：新建监控**默认用「智能体 · 提交 Git」生成**，产物落 `<仓库目录>/<源ID>/<监控ID>.py`，保存时只记 Git 路径与归档 ID、**不存脚本正文**（执行统一从 Git 取，不保留过渡版本）。
**后端不支持之前，这条路点「生成脚本」必然失败**，用户只能临时切回「内置接口」。需要后端补的是第三节 R1–R6，R7–R9 是配套事项。

---

## 二、目标链路

```
监控编辑器（新建 / 编辑监控）
 ├─ 新建：先存草稿拿监控 ID（ck_source.id）
 ├─ 生成：选智能体 + 代码仓库 + 610 目录 → 创建代码生成任务（sourceId + monitorId）
 │        → 智能体生成 → 归档提交 Git：<目录>/<sourceId>/<monitorId>.py
 ├─ 保存：check_conf 记 scriptPath（Git 路径）+ archiveId + generation，不存正文
 └─ 执行：统一调度下发任务（带脚本标识）→ 框架主程序从 Git 部署目录调用对应 .py → 回写结果
```

## 三、接口需求

### R1 代码生成任务支持「监控上下文」（契约 7）——**最优先**

现状：`POST /api/runner-management/code-generation/tasks` 必填 `sourceId / flowId / stepId / configId`（四个数字 ID），监控不是流程节点，四个里只有 sourceId。

前端已在发的请求（`runnerManagementApi.createMonitorGenerationTask`，同一端点）：

```json
{
  "sourceId": "391006829",
  "monitorId": "3101",
  "configType": "610",
  "sourceName": "源名称",
  "monitorName": "监控名称",
  "generation": {
    "configType": "610",
    "interfaceId": "all",              // 'all' = 任意空闲智能体，或具体智能体接口 ID
    "repositoryId": "<repoId>",
    "directoryId": "<directoryId>",    // 610 类型目录，2806 上是 dataMonitor
    "destinationMode": "custom",
    "autoCommit": true,
    "fileName": "3101.py",             // 固定 <monitorId>.py
    "outputSubdirectory": "391006829", // 固定 <sourceId>
    "prompt": "<用户提示词>",
    "userPrompt": "<用户提示词>",
    "systemPrompt": "<系统提示词>",
    "url": "",                         // 监控没有站点 URL
    "sampleId": "www.realcan.cn.py"
  }
}
```

需要：
1. 接受 `sourceId + monitorId`（都是数字字符串）代替 `flowId / stepId / configId`；返回与节点任务一致的 `{ job: { taskId } }`。
2. 任务详情 `GET /api/runner-management/code-generation/tasks/detail?taskId=` 沿用现有结构；成功时 `job.result` 为 `{ fileName, code, archive }`，`archive` 至少含 `archiveId / status / repoId / directoryId / files[].path / gitCommit / pushed / message`。
3. 生成后**自动提交 Git**（`autoCommit` 即最终提交，含推送）。

### R2 代码校验与文件名按节点类型区分

现状（读 `backend/runner_management` 源码）：
- `legacy_qinlongclaw/site-script-service/server.py` 的 `validate_code` 一律要求 **`scrape(url)` 函数**——监控脚本是 `def main()`，必被拒。
- `file_name_for_url` 强制校验 http(s) 站点 URL——监控没有 URL。

需要：configType = 610 时
- 不要求 `scrape(url)`；按框架约定的入口校验（R7 定下前先要求 `def main()`）。
- 不校验站点 URL，文件名直接用 `fileName`（`<monitorId>.py`）。

### R3 归档目的地按监控归属

现状：`generated_archives.destination` 归属按 `configId`，目录前缀拼 configId。

需要：监控任务归属 = `sourceId + monitorId`；仓库内路径 = `<所选目录 path>/<sourceId>/<monitorId>.py`。
（2806 上数据监控目录是 `dataMonitor`，configType 610；会上说的 `monitor` 只是示例，前端已按所选目录拼路径，不写死。）

### R4 按归档 ID 查单条（契约 4）

保存后的监控只存 `archiveId`，重新打开需要显示「commit / 已推送 / 文件路径」。
需要：`GET /api/runner-management/site-scripts/generated-results/{archiveId}`（或等价接口）返回单条归档；或 `generation-state` 支持 `?monitorId=`。

### R5 执行器改为从 Git 取脚本（契约 4）

前端保存（智能体模式）写入 `ck_source.check_conf`：

```json
{
  "generation": { "mode": "agent", "interfaceId": "all", "repoId": "...", "directoryId": "..." },
  "archiveId": "<32 位归档 ID>",
  "scriptPath": "dataMonitor/391006829/3101.py"
}
```

- **不再有 `script` 正文**，旧的内置接口正文也会删掉（避免执行到旧脚本）。
- 内置接口模式不变：照旧存 `script` + 文件服务路径。

需要：AI 监控执行器按 `scriptPath`（Git 仓库内路径）/ `archiveId` 从部署目录取脚本执行。**这一步完成前，智能体生成的监控保存后无法执行**（目前因 R1 未支持，还没有这类监控）。

### R6 「测试脚本」支持按 Git 路径试跑

现状：`POST /api/runner-management/monitor-runner/test-script` 只收脚本正文：

```json
{ "script": "...", "sourceId": "...", "tableName": "...", "timeColumn": "...", "window": { "type": "today" } }
```

需要：支持传 `scriptPath` / `archiveId`（或 `gitCommit`）代替 `script`，按 Git 版本试跑；已保存的智能体监控没有正文，只能这样测。

## 六、验收（在 186 或 2806 走一遍）

1. 新建监控 → 点「生成脚本」→ 确认先存草稿，拿到监控 ID。
2. 生成任务创建成功，任务中心可见；智能体生成完成。
3. 文件出现在 `<目录>/<sourceId>/<monitorId>.py`，脚本区显示 commit 与「已推送」。
4. 「测试脚本」按 Git 版本试跑出结果（R6）。
5. 保存后 `check_conf` 含 `generation / archiveId / scriptPath`、不含 `script`；重新打开能显示归档信息（R4）。
6. 按执行计划触发（或手动运行），执行器从 Git 取脚本跑出结果（R5，接统一调度后走 R8）。
