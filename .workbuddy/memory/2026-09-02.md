## systemPrompt 取值修正 - 取拼接后的完整提示词

- 问题：第一版取 `orchCfg.systemPrompt`，但 `loadPromptTemplate` 拼接的完整提示词只进了 RuleWorkbenchDialog 内部 `promptDraft`，没写回 `orchCfg`；用户没在工作台点「保存」时，主按钮生成脚本取到的是种子默认值/旧值，不是拼接后的完整提示词。
- 完整提示词结构：角色定义（你是一名资深数据处理专家…）+ 源表/入参字段（公众号名称:OA_ACCT,…）+ 目标表/出参字段 + ## 核心逻辑 + ## 输出要求；由 `fetchPromptList` 模板经 `applyPromptTemplate` 用当前表/字段替换占位符产出。
- 修改文件：
  - `app/src/views/FlowCanvas/inspector/RuleWorkbenchDialog.vue`：`loadPromptTemplate` 拼接成功后新增 `emit('update:systemPrompt', applied)`，把完整提示词同步写回父组件 `orchCfg.systemPrompt`。这样主按钮生成脚本时 `genCfg.systemPrompt` 取到的就是拼接后的完整值，无需用户手动保存。手动编辑的「取消不污染」仍由 `savePrompt` 显式 emit 保障。
  - `app/src/views/FlowCanvas/inspector/tabs/RuleOrchestrationTab.test.ts`：在「打开工作区后按提示词分类拉取模板并替换表配置占位符」用例加断言，验证 `orchCfg.systemPrompt` 同步写回了拼接结果（含 `源表=sense_data.TB_JD_SKU_BASE`、`入参=商品ID:sku_id`）。
- 取值链路：打开工作台 → loadPromptTemplate(fetchPromptList 模板 + applyPromptTemplate 替换占位符) → emit 写回 orchCfg.systemPrompt = 完整提示词 → 主按钮 onGenerateScript → buildDataProcessGeneratePayload(systemPrompt: genCfg.systemPrompt) → data-process 入参 systemPrompt = 完整提示词。
- 测试：RuleOrchestrationTab 27 个用例全部通过。

## LLM 生成脚本接口前端超时 120s → 5min

- 现象：data-process 接口（`/api/answer/data-process`）F12 Network 标红，但后端无报错日志、Console 也无未捕获异常——前端 `AbortController` 主动中断导致，被业务 catch 后转 `ElMessage.error`。
- 改动：`app/src/api/index.ts:915`（fetchRuleOrchestrationStream）与 `988`（fetchDataProcessGenerate）的 `controller.abort()` 超时从 `120_000` 调到 `300_000`（5min）；注释同步更新为「放宽到 5min」。
- 同类场景（长 systemPrompt 让 LLM 直接产出完整 Python 监控脚本）易超过 2 分钟，5min 足够覆盖。
- 其它超时位（auth.ts/client.ts/model.ts/prompt.ts）未动，保留各自原值。
