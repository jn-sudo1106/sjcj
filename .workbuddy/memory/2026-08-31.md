## data-process 生成脚本 500 排查 + 切本地后端

- 现象：`/api/answer/data-process` 返回 500 且后端（118.25.96.217:9999）无调用日志。直接 curl 后端复现：500 + Content-Length: 0 + `Server: nginx/1.20.1`——**该路径不在 9999 网关上**，nginx 直接回 500，请求根本没到应用层。
- 拍板（用户）：data-process 服务在本地 `127.0.0.1:8080`，开发代理要单独指过去。
- 实现：vite.config.ts 的 proxy 对象里，在 `'/api'` **之前**插入 `'/api/answer/data-process'`（Vite 代理按对象键插入顺序做前缀匹配，长前缀必须放前面才优先命中），target 取 `env.VITE_DATA_PROCESS_PROXY_TARGET` 兜底 `http://127.0.0.1:8080`，changeOrigin。
- 验证：Vite 检测到 vite.config.ts 变化自动重启 dev server；用完整报文经 5173 代理打过去 → 200，返回生成的 Python 脚本并保存到 `/code01/202608/1788176138061.py`。
- 注意：生产部署（nginx）侧的该路径路由由后端/运维处理，前端 build 产物仍是相对路径，无需改动。

## data-process 生成脚本流式打字机输出（0831）

- Bug 根因：`/api/answer/data-process` 真实返回是 **text/plain 分块流**（markdown 代码围栏 + 末行 `# 当前文件已保存到{path}`），而 `fetchDataProcessGenerate` 走 `request()` 通道会 `JSON.parse` → SyntaxError → 报「生成脚本失败」，脚本永远进不了预览框。
- 实现（三处）：
  - `legacyAdapters.ts`：`STREAM_SCRIPT_PATH_MARKERS` 追加 `# 当前文件已保存到`；新增 `parseDataProcessStreamText`（先剥保存标记行拿 scriptPath，再剥 ```python 围栏拿纯正文）。
  - `api/index.ts`：`fetchDataProcessGenerate` 重写为自管 fetch（对齐 fetchRuleOrchestrationStream 模式）：JSON body、`res.body.getReader()` 逐块读、`onChunk(delta)` 增量回调（第二参从 AbortSignal 改为 `{ signal, onChunk }` options 对象）；mock 路径不变。
  - `RuleOrchestrationTab.vue` `onGenerateScript`：规则节点分支传 `onChunk`，累计流文本剥掉开头围栏后逐块 `patch({ script })` 写回 store——脚本预览框和全屏工作台（都绑定 orchCfg.script）实时打字机效果；结束后整体解析的干净 script + scriptPath 覆盖。中途失败/取消保留已流出部分。
- 测试：ruleHttp.test.ts 的 dataProcessGenerate 用例改为真实 text/plain chunked 契约（分块 mock + onChunk 拼接断言）；legacyAdapters.test.ts 补 parseDataProcessStreamText 单测；顺手修了 f624f67 引入的存量失败（ruleOrchestrationGenerateToLegacy 断言缺 providerCode/modelCode）。共 114 测试全过，vue-tsc 零错误。真实响应体验证解析正确（51 行脚本 + scriptPath 抽出）。
- 期间教训：macOS 无 `timeout` 命令（GNU coreutils），shell 里用它会静默失败；git stash 验证存量问题时命令被 SIGTERM 中断要立刻 `git stash list` 确认再 pop。
