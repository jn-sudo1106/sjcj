  1.当日数据是否正常入库
  2.数据延迟监控

- 实现（`TableTab.vue`）：
  - `buildMonitorDescribe(tableName, methods)`：`我想对{tableName}进行如下监控：\n` + `1.方法` `2.方法`…（序号=下标+1，英文句点无空格）。

## 根因修复：已保存流程回读时 monitor 节点丢 template，系统提示词仍只显示「规则处理」

- 现象（用户最终澄清的真实场景）：数据监控节点编排配置 Tab → 编辑系统提示词 → 规则脚本工作区第一行「系统提示词」下拉框只有「规则处理」。
- 根因：之前所有测试都用「全新插入节点」（插入时 `cfg.template='monitor'` 已写），而真实场景是**加载已保存流程**。回读路径 `buildNodeForStep`（flowModel.seeds.ts）从不写 `template` 字段，导致已保存流程里的 monitor 节点 `isMonitorNode()` 恒 false，`promptCategoryGroupsForNode` 落到 `isRuleNode` 分支只给「规则处理」。
- 修复（`flowModel.seeds.ts`）：
  - `templateKeyForStep` 顶部加 `if (/数据监控/.test(name) && NODE_CONFIGS.rule) return 'rule'`——monitor 复用 rule 种子，但必须优先于下方 nodeType 别名映射，否则 nodeType='list'/'detail' 会把监控节点错路由成采集/详情节点丢掉 ruleCfg。
  - `buildNodeForStep` 加 `if (/数据监控/.test(cfg.title)) cfg.template = 'monitor'`——按节点名补回结构信号，让回读后的 monitor 仍能被 isMonitorNode 识别。
- 测试：flow.test.ts 补「从后端步骤回读，节点名数据监控补回 template=monitor」用例；promptCategory.test.ts 补「回读节点分类仍是数据监控」用例。stores(146)+promptCategory(6)+TableTab(15) 共 167 测试全过。
- 已知边界：回读依赖节点名含「数据监控」四字补 template；若用户事后把节点改名成不含该词，回读会丢 monitor 信号退化为规则处理。彻底解决需后端在 Step 里持久化节点类型（monitor 是前端新增模板，后端 Step 无 template 字段），属后续后端改动，前端已在注释标注。
