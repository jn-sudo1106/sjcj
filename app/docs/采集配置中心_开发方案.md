# 采集配置中心 · 开发方案

> 日期：2026-06-18
> 状态：开发阶段权威方案。上游依据 `docs/采集配置中心_权威方案.md`，本文件细化为可执行的工程落地计划。
> 最新进展（2026-06-25）：默认入口已从流程画布调整为一级首页 `#/overview`「采集资产总览」，7 个业务模块作为首页后的业务下钻入口保留。

## 0. 本轮决策（已拍板）

| 维度 | 决策 | 含义 |
|---|---|---|
| 开发目标 | 完善静态原型 | 仍走 mock，不接真实后端；用于评审、对齐、可交互演示 |
| 前端形态 | 工程化 | 从单文件 HTML 迁移为组件化前端工程（Vite + 框架 + 路由 + 状态） |
| 规则引擎 | 纳入本系统 | 规则资产页作为正式开发范围，含规则组/表达式/测试集/发布门禁 |
| 目录外壳 | 按独立系统调整 | 新增一级首页「采集资产总览」；7 个业务模块保留，但外层从“二级页签”升级为独立系统导航与业务入口 |

核心原则：**界面工程化 + mock 数据层按真实 `/v1` 接口 1:1 建模**。这样进入第二阶段真接入时，只替换数据适配层，不重写界面。

## 1. 技术栈

| 选型   | 方案                          | 理由                                       |
| ---- | --------------------------- | ---------------------------------------- |
| 框架   | Vue 3 + Vite + TypeScript   | 原 Data Center 为 ant-design Vue，心智与字段习惯一致 |
| UI 库 | Element Plus                | 原平台实测使用 Element UI（`el-table` 等），对齐操作心智  |
| 画布   | 自绘 SVG 画布 | 精确控制节点、连线、插入点、拖拽重排、右键菜单和运行态表达 |
| 状态   | Pinia                       | Flow/Node/Edge 草稿、选中态、mock 数据集中管理        |
| Mock | 类型化 API 客户端 + mock adapter  | 每方法对应一个真实 `/v1` 端点，换 BFF 只改 adapter      |

> 若改用 React，骨架与里程碑不变，仅替换实现层（建议 React + Vite + TS + React Flow + Ant Design + Zustand）。

## 2. 工程结构

```
src/
├─ api/              类型化接口客户端（方法名 = 真实 /v1 端点）
│  ├─ client.ts      统一请求封装 + adapter 切换（mock | http）
│  ├─ mock/          按域分文件的 mock 数据（source/config/entry/param/item-next/...）
│  └─ types.ts       领域模型 TS 类型（Source/Config/Entity/Param/Step/Task/...）
├─ stores/           Pinia：flow、assets、rules、runs、monitor
├─ views/            一级首页 + 7 个业务模块的页面级组件
│  ├─ Overview/      采集资产总览（KPI / 全景 / 趋势 / 占比 / 告警 / 下钻）
│  ├─ FlowCanvas/    流程画布（节点库 / 画布 / 节点详情 / 连线详情）
│  ├─ CollectAssets/ 采集资产（源/配置/实体/参数 + 批量 + 新建源向导）
│  ├─ RuleAssets/    规则资产
│  ├─ MetricCenter/  指标中心（dataset / measure 两层）
│  ├─ DataView/      数据查看（实体数据 / 原始文件 / JSON / 只读视图）
│  ├─ RunRecords/    运行记录（run_id 链路追溯）
│  └─ Monitor/       监控工具（只读）
├─ layouts/          独立系统外壳：顶部系统栏、侧边导航、模块标题区、内容容器
├─ components/       通用：节点卡片、抽屉、函数测试器、数据表、状态徽标
├─ router/           首页 + 7 个业务模块路由与导航元数据
└─ design/           设计令牌（迁移自现有 HTML 原型 CSS）
```

## 3. 独立系统目录与导航规范

本项目已经从 JN-WW 剥离为独立系统，目录页面不能继续表现为“宿主平台里的一个二级 Tab”。后续页面代码按以下口径调整：

### 3.1 新增一级首页，保留 7 个业务模块

当前信息架构是「首页 + 7 个业务模块」。首页承担总览和下钻，7 个模块仍为权威业务能力边界：

| 分组 | 模块 | 说明 |
|---|---|---|
| 首页 | 采集资产总览 | 默认入口，展示 KPI、采集资产全景、任务趋势、二级资产类型分布、运行动态、告警与采集周期分布 |
| 编排工作台 | 流程画布 | 默认高频入口，承载单条采集链路编排、试跑、发布 |
| 资产管理 | 采集资产、规则资产、指标中心 | 承接源、配置、规则、指标等资产治理和批量操作 |
| 运行与验收 | 数据查看、运行记录 | 承接落表验收、原始文件查看、run_id 追溯和失败定位 |
| 运维工具 | 监控工具 | 承接 MQ、函数工具、同步状态、告警等只读运维能力 |

实现上继续复用现有 `TABS` 元数据，但命名应从“页签”收敛为“首页/业务模块”。视觉上优先采用左侧系统导航或分组导航，不再把 7 个模块全部当作一排二级 Tab。

### 3.2 顶部系统栏

顶部栏用于表达“采集配置中心”作为独立系统的身份，而不是页面装饰。首期至少包含：

1. 系统名：`采集配置中心`。
2. 环境标识：`演示环境` / `测试环境` / `生产环境`，不得用 `mock` 作为正式页面标签。
3. 当前用户与权限占位：首期可用 mock 数据，但需要预留真实鉴权接入位置。
4. 帮助入口：操作手册、接口口径或发布说明入口，首期可指向文档占位。

### 3.3 默认入口

`/` 不再只被视为技术跳转。当前默认重定向到 `/overview`，先进入「采集资产总览」，再从首页下钻到流程画布、采集资产、运行记录和监控工具，避免用户进入系统后直接落入编辑器语境。

当前首页摘要与总览能力包括：

| 能力 | 目的 |
|---|---|
| KPI 总览 | 快速判断资产数量、在线源、任务量、成功率、告警和新增资产 |
| 采集资产全景 | 按设计稿展示统一数据平台与数据库、API、文件、MQ、网页采集、第三方平台的关系 |
| 任务趋势 | 用柱状图展示近 7 日 / 近 30 日抓取量与成功量 |
| 资产类型分布 | 展示二级分类占比，而不是只展示一级大类 |
| 运行动态 / 告警 | 引导进入运行记录、监控工具和采集资产处理异常 |

首页数据仍走 mock 聚合口径，真实接入时通过 `overviewApi` 替换数据适配，不改变页面结构。

### 3.4 页面视觉边界

本次不是换肤，不做营销化首页。现有后台风格、字体、主色和信息密度可以保留，但需要调整层级：

1. 系统级导航与业务内容分层清楚。
2. 模块标题区显示当前模块名称、说明和关键操作。
3. 正式演示页不展示 `mock` 字样；演示属性放到环境标识或页面角标。
4. 横向 Tab 只用于模块内部二级视图，不承担系统一级导航。

## 4. Mock 数据层契约（关键）

- `api/types.ts` 按 `docs/数据中心现有功能逆向工程_2026-06-17.md` 的 142 个 `/v1` 端点和领域模型建模。
- 每个 API 方法**一一对应一个真实端点**，签名（入参/返回）按实测字段还原：
  - 源：`sourcePaged` / `sourceDetail` / `updateSource` / `copySource` / `changeSourceEnable`
  - 配置：`configPaged` / `configDetail` / `updateConfig` / `sendConfigTask` / `updateTopic`
  - 实体：`entryTypePagedView` / `entryType` / `rebuildTable` / `rebuildIndex`
  - 参数：`paramPaged` / `genValues` / `addParamValues`
  - 子步骤：`item/next/nextConfigPaged` / `saveItemConfig` / `stepModify` / `enable` / `delete`
  - 执行：`source/sendSnatch` / `createJobs` / `task/topTaskPaged` / `job/snatchJobPaged`
  - 指标：`dataset/*` / `measure/*`
  - 监控：`mq/*` / `source/check/*` / `mq/check/*`
- adapter 默认 `mock`；切 `http` 时仅改 `client.ts` 的 baseURL（`http://115.227.21.133:9999/api/v1/`）与鉴权注入，界面零改动。
- **写类 / 高危端点**（`sendSnatch` `clear` `purgeQueue` `delete` `resetTaskInsts` 等）在 mock 层即标注 `danger: true`，UI 统一灰显或走二次确认占位，呼应权威方案读写边界。

## 6. 与现有原型的关系

- `prototypes/collect-config-center.html` 作为**视觉与交互基线**：CSS 设计令牌、节点卡片样式、连线详情字段（已对齐手册 image43）、四步向导结构直接迁移复用。
- 旧 HTML 保留在 `prototypes/`，用于对照早期设计；权威交互以 `app/src/` 工程版为准。
- 旧原型中的横向 7 Tab 可作为业务模块清单参考，但不再作为独立系统外层导航的最终视觉口径。

## 7. 边界与风险（延续权威方案）

1. 全程 mock，不直连数据库、不复制后端事实数据正文。
2. 写类/高危能力（发抓取/发配置/启停/删除/批量/清缓存/清队列）首期只读、灰显或二次确认占位。
3. 规则引擎裸开无鉴权，纳入范围后真接入前需先解决鉴权代理（M3 仅 mock，不直连 `118.25.96.217`）。
4. 登录凭据脱敏：CredentialRef 只存引用，不存明文。
