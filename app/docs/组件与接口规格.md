## 4. 架构约定

- **数据适配层三段式**：`api/endpoints.ts`（端点契约单一事实源）→ `api/client.ts`（`VITE_API_MODE=mock|http` 切换 + 未实现端点 fallback 占位）→ `api/mock/*`（按域分文件 handler）。类型化方法在 `api/index.ts`（`sourceApi`/`configApi`/`entryApi`/`paramApi`/`ruleApi`/`metricApi`/`dataApi`/`runApi`/`monitorApi`/`workbenchApi`/`flowApi`/`itemApi`），**方法名 = 真实 `/v1` 端点**。
- **端点契约**：`endpoints.ts` 收录 150 个端点（Data Center 各域趋近逆向统计 142 + 本系统自有，含流程持久化 flow/save·load·list）；其中 88 个写类/高危标 `danger`、已实现专属 mock 的由注册表处理，其余由 `client.ts` fallback 兜底（分页→空列表，写类→demo 回执），保证全部端点可调用、切 http 零改动。
- **读写边界**：`DANGER_ENDPOINTS` 由契约清单 `danger` 派生；UI 对写类/高危统一二次确认占位，mock 仅回执不落库。凭据只存引用（`CredentialRef`），明文不回显。
- **模块动作总线**：`stores/ui.ts`，业务页 `registerAction(label, fn)` 注册 AppShell 顶部按钮处理函数，离开页面 `clearActions()`；未注册即 no-op。
- **流程画布运行时**：`stores/flow.ts` 持有画布编辑态并 `serialize()/load()` 流程定义（`flowApi` localStorage 持久化）；`stores/runtime.ts` 的 `trial()` 模拟试跑（生成 run_id、节点 L→C 流转、落表数据），FlowBoard / RunRecords / DataView 三页读 runtime 叠加 mock，run_id 贯穿。
- **路由**：hash 模式，7 模块 + 导航元数据 `router/tabs.ts`。

## 5. 数据模型（`src/api/types.ts`）

源 `Source`(含 26 字段) / 分类 `SourceCategory` / 配置 `Config` / 实体 `EntryType`·`EntryField` / 参数 `Param`(列表·日期·序列) / 子步骤 `Step` / 凭据 `CredentialRef`(只存引用) / 日志 `SourceLog` / 任务 `TaskInst`；规则 `Rule`·`RuleGroup`·`RuleGate`·`RuleTestCase`·`SharedConfig`·`EvalResult`；指标 `Dataset`·`Measure`；数据查看 `DataTableMeta`·`DataRow`；运行 `RunRow`·`RunNode`；监控 `HealthCard`·`MqQueue`·`SyncRow`·`AlarmRow`；通用 `Paged<T>`·`PageQuery`·`Ack`。

## 6. 切真实后端

设 `VITE_API_MODE=http` 与 `VITE_API_BASE`（默认 `http://115.227.21.133:9999/api/v1/`），并在 `client.ts` 注入鉴权；界面与类型零改动。规则引擎真接入前需先解决鉴权代理。
